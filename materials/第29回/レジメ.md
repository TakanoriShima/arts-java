# 第29回　小さなゲームプログラムを仕上げる

## 今日の目的

第28回の機能追加を続け、既存コードを読んで自分で変更する力を確認します。完成コードの書き写しではなく、仕様・変更・確認の流れを重視します。

## 前回とのつながり

第28回では追加する機能を自分で決めました。今日は実行結果を確認し、必要な修正を行い、説明できる状態にします。

## 演習

次の確認表を使います。

| 確認 | 内容 |
|---|---|
| 読む | 変更前のクラスとMainの役割を説明する |
| 予想 | 変更後の実行結果を書く |
| 変更 | 機能を1つ以上追加・変更する |
| 実行 | Consoleの結果を確認する |
| 修正 | エラーや意図と違う結果を直す |
| 説明 | 変更箇所と理由を説明する |

## 追加例

- 敵の追加
- 回復処理
- クリティカル攻撃
- 逃走ルール
- 特殊能力

自分で考えた機能を優先します。難しい機能は、できる小ささまで分けます。

## 振り返り

- どのクラスを変更したか。
- 何を予想し、結果はどうだったか。
- 次に追加したい機能は何か。

## 発展

他の人が読んでも変更しやすい名前やメソッドになっているか確認します。
