# 第28回　能力を追加する：インタフェース

## 今回のゴール

- `interface` で「回復できる」という能力の約束を作り、`implements` でクラスに持たせられる。
- 継承の親子関係とは別に、違う種類のクラス（僧侶と敵のスライム）に同じ能力を持たせられる。
- 既存のバトルに、手順を追って機能を追加できる（仕様 → 変更箇所 → 実装 → 実行 → 確認）。

## 前回とのつながり

第27回で、バトルの基準版ができた。今回は「回復魔法」を追加する。回復できるのは、味方の僧侶だけではない。敵の中にも、仲間を回復するスライムを作りたい。

- `Character` に回復魔法を書くと、魔法使いや戦士まで回復できてしまう。
- 僧侶は `Character` の子、スライムは `Enemy` の子で、親が違う。Java では、1 つのクラスが `extends` できる親は **1 つだけ**。

そこで、親子関係とは別に「回復できる」という能力だけを表す **インタフェース** を使う。

## 講義内容

### 1. インタフェース：能力の約束

`プログラム/第28回/sample/battle/Healer.java`

```java
package battle;

// インタフェース：「回復できる」という能力の約束
// implements したクラスは、cure メソッドを必ず書く
public interface Healer {
    void cure(Character target);
}
```

- `interface` には、メソッドの **名前・引数・戻り値の型** だけを書く（中身は書かない）。第23回の抽象メソッドと同じ形。
- `new Healer()` のように、インタフェースそのもののインスタンスは作れない。

### 2. implements：約束を守るクラス

`プログラム/第28回/sample/battle/Priest.java`

```java
package battle;

// 僧侶：Character を受けつぎ、Healer（回復できる）の約束も守る
public class Priest extends Character implements Healer {
    public Priest(String name, int hp, int power) {
        super(name, hp, power);
    }

    @Override
    public void attack(Character target, int turn) {
        System.out.println(getName() + "は杖でたたいた！ " + target.getName() + "に" + getPower() + "のダメージ");
        target.damage(getPower());
    }

    // Healer の約束：回復の祈り（12 回復）
    @Override
    public void cure(Character target) {
        target.heal(12);
        System.out.println(getName() + "は回復の祈りをささげた！ " + target.getName() + "のHPが" + target.getHp() + "になった");
    }
}
```

- `extends Character implements Healer` は、「`Character` の子であり、`Healer` の約束も守る」という意味。
- `implements` したら、インタフェースのメソッド（`cure`）を **必ず `public` で** 書く。インタフェースのメソッドは、自動的に `public` 扱いになっているため。
- インタフェースは、1 つのクラスにいくつでも `implements` できる（`implements A, B` のように `,` で区切る）。`extends` は 1 つだけ。

| | 抽象クラス（`Character`） | インタフェース（`Healer`） |
|---|---|---|
| 表すもの | 「何の一種か」（親子関係） | 「何ができるか」（能力） |
| 書けるもの | フィールド、コンストラクタ、ふつうのメソッド、抽象メソッド | メソッドの約束 |
| いくつ持てるか | `extends` は 1 つだけ | `implements` はいくつでも |

### 3. インタフェース型で扱う

`プログラム/第28回/sample/battle/Main.java`（追加したところ）

```java
String[] commands = { "攻撃", "薬草を使う", "にげる", "ためる", "回復魔法" };
```

```java
case 5:
    // 回復できる（Healer の）仲間が、いちばん HP の少ない仲間を回復する
    boolean healed = false;
    for (Character member : party) {
        if (member instanceof Healer) {
            Healer healer = (Healer) member;
            healer.cure(findWeakest(party));
            healed = true;
        }
    }
    if (!healed) {
        System.out.println("回復魔法を使える仲間がいない！");
    }
    break;
```

```java
// HP がいちばん少ないメンバーを返す
static Character findWeakest(ArrayList<Character> members) {
    Character weakest = members.get(0);
    for (Character member : members) {
        if (member.getHp() < weakest.getHp()) {
            weakest = member;
        }
    }
    return weakest;
}
```

- `member instanceof Healer` は、「`member` の中身は `Healer` の約束を守るクラスか」を調べる（第22回で読んだ `instanceof` と同じ）。
- `(Healer) member` で `Healer` 型として扱うと、`cure` を呼べる。
- `Main` は、回復しているのが僧侶かどうかを知らない。「回復できる者なら回復して」と命令しているだけ。後で回復できる職業を増やしても、この `case 5` は変えなくてよい。
- `findWeakest` は、「今までで一番少ない人」を覚えておき、もっと少ない人が見つかったら入れかえる、という最小値を探す形。

## 演習２　既存のバトルに機能を追加する

`java28_exercise` を作り、`battle` パッケージに `プログラム/第28回/exercise/battle/` の 8 ファイルを入れる。

機能を追加するときは、いきなり書き始めず、次の順番で進める。

1. **仕様**：何ができるようになるかを 1 文で書く。
2. **変更箇所**：どのファイルの、どのメソッドを変える（作る）か書き出す（第27回の「どこを変えると何が変わるか」の表を使う）。
3. **実装**：1 か所ずつ書く。
4. **実行・確認**：予想した結果になるか確かめる。

### 演習２-１　いやしスライムを作る

- 仕様：「なかまの敵を 10 回復できる、いやしスライムが出てくる」
- 変更箇所：
  - 新しいクラス `HealSlime`：`Enemy` を受けつぎ、`Healer` を `implements` する。コンストラクタは `Enemy` と同じ 4 つの引数。
  - `cure` は `target.heal(10)` で回復し、`いやしスライムはなかまを回復した！ ゴブリンのHPが22になった` の形で表示する。
  - `Main` の敵のグループに、いやしスライム（HP 25、攻撃力 3、経験値 20）を追加する。
- この時点では、いやしスライムはふつうに攻撃するだけ。回復はまだしない。

### 演習２-２　敵のターンで回復させる

- 仕様：「いやしスライムは、弱っている敵（HP が最大の半分より少ない）がいれば、攻撃の代わりに回復する」
- 変更箇所：`Main` の `enemyTurn`。弱っている敵は、配布ファイルにある `findWeakestEnemy(enemies)` で探せる。

ヒント：

```java

if (enemy instanceof Healer && weakest.getHp() < weakest.getMaxHp() / 2) {
    // Healer 型に変換して cure を呼ぶ
} else {
    // 今までの攻撃の処理
}
```

### 演習２-３　戦士をよろいで守る

- 仕様：「戦士は、受けるダメージを 2 へらせる（ただし最低 1 は受ける）」

## 確認問題

**問1**　コンパイルできるか。

```java
Healer h = new Healer();
```

**問2**　次のクラスはコンパイルできるか。

```java
public class Fairy implements Healer {
    void cure(Character target) {
        target.heal(5);
    }
}
```

**問3**　次のコードはコンパイルできるか（クラスはサンプルと同じ）。

```java
Healer h = new Priest("僧侶", 25, 4);
h.attack(new Warrior("戦士", 40, 10), 1);
```

<details>
<summary>答え</summary>

- 問1：できない（インタフェースはインスタンスを作れない）
- 問2：できない（`cure` に `public` がない。インタフェースのメソッドを実装するときは `public` が必要）
- 問3：できない（変数の型は `Healer`。`Healer` には `cure` しかないので、`attack` は呼べない。第22回と同じ考え方）

</details>
