## 講義内容

### 1. エラーの 3 つの種類

| 種類 | いつ分かるか | 例 | 見つけ方 |
|---|---|---|---|
| コンパイルエラー | 保存したとき・実行する前 | `;` がない、型が合わない、名前の書き間違い | Pleiades の赤い印とメッセージ |
| 実行時エラー（例外） | 実行している途中 | 範囲外の添字、`null` のまま使う、数字以外の入力 | コンソールの赤い文字（`Exception in thread "main" ...`） |
| 論理エラー | 実行結果を見たとき | 計算式・条件の間違い | 予想と実行結果を比べる。**エラーは表示されない** |

### 2. 実行時エラーの読み方

```text
Exception in thread "main" java.lang.IndexOutOfBoundsException: Index 3 out of bounds for length 3
	at java.base/java.util.ArrayList.get(ArrayList.java:428)
	at battle.Main.main(Main.java:56)
```

1. 1 行目：例外の種類とメッセージ。「長さ 3 のリストで、3 番を使おうとした」。
2. `at ...` の行を上から見て、**自分が書いたクラス**（`battle.` で始まる行）を探す。`Main.java:56` なら、`Main.java` の 56 行目。
3. その行で、何の値がおかしいのか考える。

| よく出る例外 | 意味 |
|---|---|
| `ArrayIndexOutOfBoundsException` / `IndexOutOfBoundsException` | 配列・リストにない番号を使った |
| `NullPointerException` | `null`（何も入っていない変数）のメソッドを呼んだ |
| `InputMismatchException` | `nextInt()` で整数以外が入力された |
| `ArithmeticException` | 0 で割った |

### 3. try-catch：例外が起きたときの処理を書く

`プログラム/第26回/sample/battle/Main.java`（変わったところ）

```java
import java.util.InputMismatchException;
```

```java
static int inputCommand(Scanner scanner, String[] commands) {
    for (int i = 0; i < commands.length; i++) {
        System.out.println((i + 1) + ": " + commands[i]);
    }
    int command = 0;
    do {
        System.out.print("コマンドを選ぶ > ");
        try {
            command = scanner.nextInt();
        } catch (InputMismatchException e) {
            // 数字以外が入力されたときは、ここに来る
            System.out.println("数字を入力してください");
            scanner.next();   // 読めなかった入力を捨てる
        }
    } while (command < 1 || command > commands.length);
    return command;
}
```

- `try { }` の中で例外が起きると、そこで中断して `catch { }` の中に移る。例外が起きなければ、`catch` の中は実行されない。
- `catch (InputMismatchException e)` は、「この種類の例外が起きたとき」という意味。
- `scanner.next();` で、読めなかった文字（例：`a`）を捨てないと、次の `nextInt()` でも同じ文字を読もうとして、くり返し失敗する。
- `command` の最初の値を `0` にしておくことで、失敗したときは `while` の条件で聞き直しになる。
- `try-catch` は、この授業では「読んで意味が分かる」ことを目標にする。自分で書けなくてもよい。

### 5. エラーを直すときの手順

1. **いちばん上のエラーから** 1 つずつ直す。1 つのまちがいが、ほかのエラーを引き起こしていることがある。
2. 行番号の行だけでなく、**その前の行** も見る（`;` の書き忘れは、次の行でエラーになることがある）。
3. 直したら、保存して、もう一度実行する。
4. 論理エラーは、「正しいときはどうなるはずか」を先に決めておき、実行結果と比べて見つける。

## 確認問題

**問1**　次のまちがいは、それぞれどの種類のエラーか（コンパイルエラー／実行時エラー／論理エラー）。

1. `int x = "3";`
2. `int[] a = new int[2];` の後に `a[2] = 1;`
3. 回復の処理で、`Math.min` を使うべきところを `Math.max` にした。

**問2**　出力は何か。

```java
try {
    System.out.println("A");
    int[] a = new int[1];
    a[5] = 0;
    System.out.println("B");
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("C");
}
System.out.println("D");
```

**問3**　次のコードを実行すると、どの例外が起きるか。

```java
String name = null;
System.out.println(name.length());
```

<details>
<summary>答え</summary>

- 問1：1. コンパイルエラー（型が合わない）　2. 実行時エラー（添字は 0 と 1 だけ）　3. 論理エラー（エラーは出ないが結果がおかしい）
- 問2：`A`、`C`、`D`（`a[5]` で例外が起きた時点で `catch` へ移るので、`B` は表示されない）
- 問3：`NullPointerException`（`null` の変数のメソッドを呼んでいる）

</details>
