## 進め方と時間

| 時間 | 内容 |
|---|---|
| 0〜10分 | 自己紹介・後期の説明・Java実行確認 |
| 10〜25分 | 基本文法：1Aを読む、1Bを書く |
| 25〜43分 | メソッド：2Aを読む、2Bを書く |
| 43〜68分 | OOP：3を読む（8分）、4を書く（10分）、5を読む（5分）、確認（2分） |
| 68〜80分 | 総合ミニプログラム：6を書く |
| 80〜86分 | Bronze形式：7の2問 |
| 86〜90分 | 振り返り |

時間は授業進行の目安です。時間切れの問題は「未」として先へ進みます。
各区間の最後の2〜3分は実行・修正・短い解説に使います。

- 読む問題は、実行する前の予想を必ず残します。実行後に予想を消さず、実際の結果を追記します。
- 書く問題は最初の数分は個人で挑戦し、その後はヒントや例を利用できます。
- sampleは講師の実演・解説用の完成例です。最初の挑戦では開かず、読む問題の指定ファイルだけを開きます。
- ヒントや完成例を見て解けた場合も大切な成果です。何を見たか記録しましょう。
- 編集するのはexerciseです。配布した枠や完成済みクラスは利用して構いません。

### 診断の記録

| 記号 | 状態 |
|---|---|
| A | ヒントなしでできた |
| B | ヒントや例を見てできた |
| C | 解説後も再確認が必要 |
| 未 | 時間不足などで未着手 |

「未」は理解不足という意味ではありません。途中まで取り組んだ場合は、できた箇所と止まった箇所をメモし、解説後にA〜Cを判断します。
配布済みのコードの枠を使うだけならBにはしません。4は直前の例を応用する問題なので、例を見た場合はBと記録します。
読む力と書く力は別々に記録します。
