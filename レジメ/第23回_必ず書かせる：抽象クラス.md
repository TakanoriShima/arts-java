## 講義内容

### 1. abstract：new できないクラス

`プログラム/第23回/sample/Character.java`（変わったところ）

```java
// 抽象クラス：Character そのものは new できない。必ず Hero や Enemy などの子クラスを作って使う
public abstract class Character {
    ...

    // 抽象メソッド：攻撃のしかたはキャラクターごとに違うので、子クラスで必ず書く
    public abstract void attack(Character target, int turn);

    // ふつうの攻撃（子クラスの attack の中から使える）
    public void normalAttack(Character target) {
        System.out.println(name + "の攻撃！ " + target.getName() + "に" + power + "のダメージ");
        target.damage(power);
    }

    ...
}
```

| 書き方 | 意味 |
|---|---|
| `public abstract class Character` | **抽象クラス**。`new Character(...)` ができない |
| `public abstract void attack(...);` | **抽象メソッド**。中身（`{ }`）を書かず、`;` で終わる。子クラスで必ずオーバーライドする |

- 抽象クラスにも、ふつうのフィールド・コンストラクタ・メソッドを書ける。HP の管理などの共通部分は、今までどおり `Character` に残る。
- `Character` 型の変数や配列は、今までどおり使える（`Character[] party` など）。作れないのは `Character` そのもののインスタンスだけ。

### 2. ふつうの攻撃は normalAttack に

第21回・第22回では、会心の一撃でないターンに `super.attack(...)` で親クラスの攻撃を使っていた。`attack` が抽象メソッドになって中身がなくなったので、ふつうの攻撃を `normalAttack` という別の名前で `Character` に残した。

`プログラム/第23回/sample/Hero.java`（変わったところ）

```java
@Override
public void attack(Character target, int turn) {
    if (turn % 3 == 0) {
        ...
    } else {
        normalAttack(target);   // Character のふつうの攻撃
    }
}
```

`Enemy.java` も同じように、強攻撃でないターンは `normalAttack(target)` を呼ぶ。

### 3. 実行する前に予想する

`Main.java` では、敵が強いトロル（HP 110、攻撃力 12）に変わった。`1`、`1`、`1`、`2`、`1`、`1` の順に入力する。

- 4 ターン目のトロルの攻撃はどうなるか（`Enemy` の `attack` を読む）。
- たおれたメンバーは、次のターンに攻撃するか（`Main` の `case 1` を読む）。

### 5. エラーを体験する

1. `Main.java` の `main` の最初に、`Character someone = new Character("謎の人", 10, 1);` と書いて保存する。
2. `Character` は抽象クラスなのでインスタンスを作れない、というエラーになることを確認する。確認したら消す。
3. `Wizard.java` の `attack` メソッド（`@Override` から `}` まで）を、コメントにして保存する（範囲を選んで `Ctrl` + `/`）。
4. `Wizard` が抽象メソッド `attack` を実装していない、というエラーになることを確認する。Pleiades では、エラーの印をクリックすると「実装されていないメソッドの追加」という修正候補が出ることもある。
5. コメントを外して元に戻す。

- 第22回までは、`attack` を書き忘れてもエラーにならず、気付かないまま「ふつうの攻撃」になっていた。抽象メソッドにすると、**書き忘れをコンパイラが見つけてくれる**。

## 前半の確認（15分）

第16回〜第22回で学んだことの確認。何も見ずに解く。

**問1**　出力は何か。

```java
int x = 17;
System.out.println(x / 5 + " " + x % 5);
```

**問2**　出力は何か。

```java
String[] s = { "A", "B", "C" };
for (int i = s.length - 1; i >= 0; i--) {
    System.out.print(s[i]);
}
```

**問3**　出力は何か。

```java
public static void main(String[] args) {
    System.out.println(twice(twice(3)));
}

static int twice(int n) {
    return n * 2;
}
```

**問4**　出力は何か（クラスはサンプルと同じ）。

```java
Character a = new Hero("勇者", 30, 8, 2);
Character b = a;
b.damage(10);
System.out.println(a.getHp());
```

**問5**　`Main` クラスで `hero.hp = 5;` と書いた。コンパイルできるか。理由も答える。

**問6**　出力は何か（クラスはサンプルと同じ）。

```java
Character c = new Warrior("戦士", 40, 10);
c.attack(new Warrior("的", 50, 1), 1);
```

<details>
<summary>答え</summary>

- 問1：`3 2`（第16回：整数の割り算と余り）
- 問2：`CBA`（第17回：配列と `for`。最後の添字は `length - 1`）
- 問3：`12`（第18回：内側の `twice(3)` が先に 6 を返し、`twice(6)` が 12 を返す）
- 問4：`20`（第19回：`a` と `b` は同じインスタンスを指す）
- 問5：できない。`hp` は `private` なので、`Character` の外から使えない（第20回）
- 問6：`戦士のおのの一撃！ 的に10のダメージ`（第21回・第22回：動くのは中身の `Warrior` の `attack`）

間違えた問題の回のレジメを、次回までに読み直す。

## 確認問題

**問1**　コンパイルできるか。

```java
abstract class Monster {
    abstract void cry();
}
```

```java
Monster m = new Monster();
```

**問2**　出力は何か。

```java
abstract class Monster {
    void hello() {
        System.out.println("やあ");
    }

    abstract void cry();
}

class Slime extends Monster {
    @Override
    void cry() {
        System.out.println("ぷる");
    }
}
```

```java
Monster m = new Slime();
m.hello();
m.cry();
```

**問3**　問2の `Monster` を使って、次のクラスを作った。コンパイルできるか。

```java
class Bat extends Monster {
}
```

<details>
<summary>答え</summary>

- 問1：できない（抽象クラスはインスタンスを作れない）
- 問2：`やあ` と `ぷる`（抽象クラスにもふつうのメソッドを書ける。`Monster` 型の変数に子クラスのインスタンスを入れられる）
- 問3：できない（抽象メソッド `cry` を実装していない）

</details>
